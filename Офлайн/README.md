# Управление на основе данных

**Оффлайн-интенсив для топ-менеджмента здравоохранения. 3 дня. 3 воркшопа. 3 проекта. Один сквозной кейс.**

---

## Две версии интенсива

Интенсив существует в двух вариантах по трудоёмкости — сюжет, датасет, словарь и персонажи у них общие, различается только объём проектов. Версии лежат в **разных папках**:

| Версия | Нагрузка | Состав дня | Где лежит |
|--------|----------|------------|-----------|
| **Полная (недельная)** | ~9–11 ч практики/день | 6 заданий | `День_N_final/` · обзор — [`overview_final.md`](overview_final.md) |
| **На 5 часов/день** | ~5 ч практики/день, таймер на каждое задание | **4 основных + 2 бонусных** | [`5_часов/`](5_часов/) · обзор — [`5_часов/overview.md`](5_часов/overview.md) |

**Версия на 5 часов** рассчитана на аудиторию с нулевым уровнем в data-направлении: на каждый день оставлены 4 задания, держащие сквозную линию (дерево → гипотезы → ТЗ → проверка → Impact Map → KPI → защита), а 2 задания вынесены в бонус (делаются, если осталось время). Строгость и образ результата основных заданий сохранены — сокращён **объём**, а не **сложность**. Папка `5_часов/` самодостаточна (со своими `materials/`); полная версия в `День_N_final/` не изменялась.

Описание ниже относится к **полной версии**. Для версии на 5 часов открывайте папку [`5_часов/`](5_часов/).

## Структура каждого дня

**Полная версия** — `День_N_final/`:

```
День_N_final/
├── readme.md         # Проект дня: 6 заданий
├── check_list.md     # P2P-чек-лист защиты артефактов
├── workshop.md       # Структура воркшопа (75–90 мин)
└── materials/        # Шаблоны и примеры артефактов
    ├── template_*.md   # Шаблоны для заполнения группой
    └── *_example.md    # Примеры готовых артефактов
```

**Версия на 5 часов** — `5_часов/` (самодостаточна, со своими `materials/`):

```
5_часов/
├── overview.md       # Обзор для этой версии
└── День_N/
    ├── readme.md     # 4 основных задания с таймерами + 2 бонусных
    ├── check_list.md # Чек-лист (бонусы — отдельным блоком)
    ├── workshop.md   # Воркшоп с подводками под состав дня
    └── materials/    # Своя копия шаблонов и примеров
```

## Дуга интенсива

| День | Воркшоп | Проект | Главный артефакт |
|------|---------|--------|------------------|
| 1 | Фундаментальные принципы Data-Driven и роль ИИ | Дизайн подхода на основе данных | Дерево факторов + 5 гипотез + ТЗ для МИАЦ |
| 2 | Обработка и анализ данных | Анализ данных и проектирование дашборда | Wireframe + геокарта + аналитическая записка |
| 3 | Принятие решений на основе данных | От инсайтов к стратегии | Impact Map + KPI «to-be» + презентация защиты |

День 2 опирается на гипотезы и ТЗ Дня 1. День 3 опирается на инсайты Дня 2. Пропуск дня ломает логику.

## Сквозной кейс — одной фразой

**Регион Б** — условный субъект РФ с летальностью на 25–40 % выше, чем у соседнего благополучного **Региона А**. Президентское поручение: сократить разрыв на 30 % к 2027 году. Финансирование федеральное — при условии защищаемой программы. Группа — управленческий штаб Региона Б. Три дня — на разработку защищаемого решения.

Подробно — в [`overview_final.md`](overview_final.md).

## Формат работы

- **Группы по 3–5 человек.** Каждая группа — управленческий штаб одного условного региона. Распределение ролей внутри группы: министр / главврач / МИАЦ / фонд ОМС.
- **Утро** — воркшоп (60–90 мин). Без классических лекций — ведущий разворачивает структуру, группы реагируют, спорят, делают микропрактики.
- **День** — проект из 6 заданий.
- **Вечер** — взаимная защита по P2P-чек-листу. Чем дотошнее проверка — тем выше польза.

## Инструменты

- **ИИ-ассистенты** (GigaChat / YandexGPT / ChatGPT) — главный инструмент. Промпт-инжиниринг, генерация гипотез, очистка данных, саммари, структура презентации.
- **Miro / FigJam / лист А3** — для wireframe дашбордов, Impact Map, геокарты.
- **PowerPoint / Keynote / Google Slides** — для итоговой презентации.
- **Текстовые файлы (`.md`, `.docx`)** — для ТЗ, аналитических записок, KPI-карт.

Никакого Excel / SQL / Python для участников. Участники — управленцы, не аналитики.

## Отличия офлайн-формата от стандартных правил школы

Базовая методология (`../Правила/`) описывает онлайн-формат с GitLab и автоматизированной проверкой. Этот интенсив адаптирован под топ-менеджмент и в части процедурных правил отличается:

| Стандартное правило | В офлайн-интенсиве |
|---------------------|--------------------|
| Сдача в GitLab, папка `src/`, ветка `develop` | Сдача на общий диск группы: `src/<номер_группы>/День_N/`. Git и ветки не используются. |
| Автотесты / код-ревью | Только P2P-защита по чек-листу (вечером каждого дня) |
| EMPTY WORK / CHEAT | **Работают как обычно**: EMPTY WORK — если папка пуста или нет защиты; CHEAT — если группа не может объяснить артефакт голосом. |
| Содержание «без инструкций» (только облако тегов) | Сознательное отклонение: задания дают пошаговые инструкции — топ-менеджмент в этом формате не разбирается из шаблонов проектов. Образ результата, ограничения и подсказки остаются. |
| Excel / SQL / Python для участника | Запрещены. Все расчёты — у координатора (генератор) и в готовых агрегатах (`materials/precomputed_summary.md`). |

Если у группы возник вопрос «а что говорят правила школы по поводу X» — для X из таблицы выше правила интенсива **отменяют** стандарт. По остальным вопросам (peer-to-peer, обязательность взаимной проверки, флаги, P2P-экономика времени) — действуют общие правила.

## Подготовка датасета (для координатора, не для участников)

Координатор интенсива заранее, **до начала Дня 1**, генерирует датасеты и кладёт их в общую папку группы (Google Drive / общий диск):

```
python3 shared_dataset/create_datasets.py
```

Создаст три CSV-файла:
- `dataset_v1.csv` — сырая годовая выгрузка для Дня 1
- `dataset_v2.csv` — помесячная динамика + кадры + оборудование для Дня 2
- `dataset_v3.csv` — + плановые показатели + 2022 год + Федпроект для Дня 3

Воспроизводимо: `random.seed(42)`. У всех групп одинаковые числа.

Участники команду `python3` **не запускают** — они работают с готовыми CSV как с обычными файлами (открывают глазами, не считают). Подробно — в [`shared_dataset/data_dictionary.md`](shared_dataset/data_dictionary.md).

## Как начать

1. Прочитать [`overview_final.md`](overview_final.md) до начала первого дня.
2. **Координатор** заранее запускает генератор данных и кладёт три CSV в общую папку.
3. Распределить роли в группе.
4. Открыть [`День_1_final/workshop.md`](День_1_final/workshop.md) → провести воркшоп Дня 1 → перейти в [`День_1_final/readme.md`](День_1_final/readme.md).
5. К концу Дня 1 у группы должны быть 6 артефактов в общей папке `src/<номер_группы>/День_1/`.
6. День 2 → День 3 → защита.

## Связь с онлайн-курсом «Здоровье+»

Оффлайн-интенсив **не повторяет и не заменяет** 6-проектный онлайн-курс для аналитиков. Это **параллельный продукт** для другой аудитории:

| | Онлайн-курс (project_1…project_6) | Оффлайн-интенсив |
|---|------------------------------------|------------------|
| Аудитория | Младшие аналитики | Топ-менеджмент здравоохранения |
| Длительность | 6 проектов, недели | 3 дня |
| Кейс | Сеть частных клиник «Здоровье+» | Два условных субъекта РФ |
| Артефакты | Excel-таблицы, SQL-запросы, Python-скрипты, Dash-дашборды | Документы, wireframe-макеты, ТЗ, презентации |
| Главный инструмент | Excel → SQL → Pandas → Plotly → SciPy → scikit-learn | ИИ-ассистенты + Miro + PowerPoint |
| Формат | Индивидуально | Группа 3–5 человек |
| Роль участника | Делает анализ | Заказывает анализ и принимает решения |

Если хочешь увидеть, как тот же подход выглядит «с другой стороны стола» — посмотри корневой [`../README.md`](../README.md) онлайн-курса.
