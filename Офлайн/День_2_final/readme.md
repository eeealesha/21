### Задание 1: Аудит выгрузки от МИАЦ

**Для выполнения нужно знать:** типичные ошибки медицинских данных (опечатки в кодах, дубли пациентов, аномалии времени, пропуски, выбросы), различие между «техническим браком» и «содержательной аномалией».

ТЗ ушло — выгрузка пришла. Прежде чем считать гипотезы, убедитесь, что вы считаете не мусор.

**Проходной порог — найти 6 из 8 классов. Найти все 8 — на отличную оценку.**

**Выполни следующие шаги:**

1. Откройте `dataset_v2.csv` в Numbers / Google Sheets. **Применяйте 6 приёмов поиска** — этого хватает на 7 из 8 классов:
   - **Сортировка по `time_to_ivl_min`** (по возрастанию) — увидите аномально низкие значения (4 мин) **и** подозрительные значения с 3 знаками после запятой (восстановленные данные).
   - **Фильтр `vacancy_reanim_pct < 0`** — найдёте отрицательную вакансию.
   - **Сортировка по `month`** в алфавитном порядке — опечатки названий (`сентябь`, `янврь`, `нобярь`) встают рядом с нормальными значениями.
   - **Сводная по `(mo_id, year, month)` с подсчётом** — дубликат ключа покажется как `count = 2`.
   - **Фильтр в `population` по нечисловым значениям** (или сортировка по столбцу — нечисловые встанут в конец) — найдёте `н/д`.
   - **Фильтр `ivl_units = 0`** (или сортировка по `ivl_units` снизу) — найдёте несогласованность: нулевое количество аппаратов ИВЛ при ненулевом `time_to_ivl_min` («как ИВЛ запускалась, если её нет?»).

   Восьмой класс (содержательные нули `letality_pct` при ненулевом `admitted`) — **сортировка по `letality_pct` снизу**.

   **Не считайте формулами анализа** — задача аудита, не анализа.
2. Сформулируйте промпт для ИИ-аудитора: роль «опытный data quality инспектор Минздрава», задача — подтвердить ваши находки и предложить дополнительные классы проблем, которые вы могли пропустить. Шаблон — в [`materials/template_data_quality_review.md`](materials/template_data_quality_review.md).
3. Покажите ИИ структуру файла (заголовки + 10 первых строк) и попросите построить **гипотезы о возможных проблемах** до того, как вы их найдёте.
4. Проверьте каждую гипотезу аудита вручную (просмотр глазами + сортировка по столбцу). По каждой запишите: подтвердилось / нет, на скольких строках, что это значит для дальнейшего анализа.
5. Для проблем класса «технический брак» (опечатки, пропуски, выбросы значений) сформулируйте, как именно исправлять (заменять на медиану / отбрасывать строки / запрашивать у МИАЦ повтор).
6. Для проблем класса «содержательная аномалия» (например, аномально низкое время до ИВЛ в одной МО) сформулируйте, **какие управленческие действия** должны последовать — *не правка данных, а проверка процесса в МО*.

**Результат:** файл `task1_data_quality_review.md` в папке группы.

> Важно различать: технический брак исправляется в файле; содержательная аномалия исправляется в реальности.

### Задание 2: Проверка гипотез Дня 1

**Для выполнения нужно знать:** корреляция vs причинно-следственная связь, понятие конфаундера (третьей переменной), почему «эффект на средние» может скрывать обратный эффект на подгруппе.

Берёте 3–5 гипотез из вчерашнего файла `task4_hypotheses.md`. Сегодня — момент истины.

**Выполни следующие шаги:**

1. Для каждой гипотезы сформулируйте промпт к ИИ: «У нас вот такой датасет с такими полями [список]. Гипотеза: [текст]. Опиши пошагово, какой анализ нужно сделать, чтобы её проверить (на словах, без кода). Что должно получиться, если гипотеза верна? Что — если неверна?»
2. Запишите план проверки для каждой гипотезы. На этом этапе вы **не считаете**, а формулируете методику.
3. Откройте сводную справку [`materials/precomputed_summary.md`](materials/precomputed_summary.md) — там собраны готовые агрегаты по основным разрезам датасета (по регионам, по уровням вакансий, по `time_to_ivl_min`, по 3 «горячим» МО). Сопоставьте цифры справки с каждой гипотезой. **Если для какой-то гипотезы нужного среза в справке нет — это тоже результат:** значит, вы спросили данные, которых пока не считают, и это пункт в ТЗ для МИАЦ v2 (День 3).
4. По каждой гипотезе зафиксируйте вердикт:
   - **Подтверждена** (с цифрой эффекта)
   - **Опровергнута**
   - **Частично подтверждена** (объясни, в каких подгруппах работает, в каких нет)
   - **Невозможно проверить на этих данных** (объясни, чего не хватает)
5. **Отдельным разделом — три предупреждения о причинности.** Где в вашем анализе наибольший риск спутать корреляцию с причиной? Что вы НЕ имеете права утверждать перед губернатором даже если корреляция есть?

### Задание 3: Wireframe дашборда главврача

**Для выполнения нужно знать:** принципы UI/UX дашборда (одна цель = один дашборд, верхняя строка — ключевые KPI, фильтры справа, инсайт сверху-слева), правило «5 секунд» (за 5 секунд должно быть видно главное), различие операционного и стратегического дашборда.

Главврач крупной МО Региона Б — пользователь номер один. Он не аналитик. Он смотрит дашборд утром между обходами. Если за 5 секунд непонятно, **что нужно делать** — дашборд не работает.

**Выполни следующие шаги:**

1. Сформулируйте, какое **управленческое действие** должен провоцировать дашборд (одно предложение). Без этого — не начинайте.
2. На листе А3 (или в Miro/FigJam) нарисуйте wireframe. **Опорный ASCII-эскиз правильной компоновки и анти-дашборда + пример спецификации виджета** — в [`materials/template_wireframe.md`](materials/template_wireframe.md). Используйте как референс, **не копируйте**: ваш дашборд решает **конкретное** управленческое действие, не «вообще». Минимальные требования:
   - 4–6 виджетов
   - Верхняя строка — 3–4 KPI с цветовым кодом
   - Левая большая зона — главный график/тепловая карта
   - Правая колонка — фильтры (период, МО, специальность)
   - Внизу — таблица «топ-5 проблемных МО» или аналогичный «список к действию»
3. Для каждого виджета на отдельном листе/в подписи объясните: что меряет, какой источник из `dataset_v2.csv`, какое действие провоцирует.
4. Сделайте **анти-дашборд** на отдельном листе: тот же набор данных, но в виде «отчёт ради отчёта» (5 пай-чартов, 3D-эффекты, легенды на половину экрана). Это контраст, который должен прийти на P2P-защиту.
5. Покажите ИИ описание главного виджета и спросите: «Какие 3 типовые ошибки UI/UX в этом виджете я могу совершить?» Запишите ответ и проверьте свой wireframe против него.

**Результат:** `task3_wireframe.png` (скан/экспорт макета) + `task3_dashboard_spec.md` (текстовое описание).

### Задание 4: Геокарта проблемных МО

**Для выполнения нужно знать:** разница между табличным и пространственным представлением, понятие «горячей точки», ограничения геоаналитики (плотность населения, удалённость от центра).

Цифры в таблице — мёртвые. Те же цифры на карте — живые. Сегодня вы переносите 24 МО на условную карту региона.

**Выполни следующие шаги:**

1. На листе А3 или в Miro начертите две условные карты (Регион А и Регион Б) с прямоугольной сеткой районов. Расставьте 24 МО.
2. Для каждой МО нанесите цветовой код по летальности (зелёный / жёлтый / красный) на основе годового агрегата из `dataset_v2.csv`.
3. **Вторым слоем** — размер кружка пропорционален обслуживаемой популяции. Это критично: маленькая МО с красной летальностью — другой уровень проблемы, чем большая.
4. Найдите **2–3 «горячие точки»** — МО, которые красные и большие одновременно. Это ваши приоритеты.
5. Найдите **1–2 контринтуитивных места**: МО с большой популяцией, но зелёные. Что вы можете у них перенять?
6. Отдельным абзацем — **ограничения геоаналитики**: что эта карта НЕ показывает? (Например, она не показывает потоки пациентов между МО, маршрутизацию скорой, плотность населения внутри района.)

### Задание 6: Аналитическая записка для зам. губернатора

**Для выполнения нужно знать:** структура аналитической записки (Контекст → Главный вывод → 3 ключевых факта → Решение → Риски), правило «один экран, одна страница», язык управленческой коммуникации (без p-value, без терминологии).

Зам. губернатора прочитает вашу записку за 90 секунд между двумя совещаниями. Если за 90 секунд он не поймёт, **что вы предлагаете и почему**, — записка провалилась.

**Выполни следующие шаги:**

1. Откройте `task1_data_quality_review.md`, `task2_hypotheses_check.md`, `task3_dashboard_spec.md`, `task4_geomap_notes.md` — это весь ваш материал.
2. Сформулируйте промпт к ИИ: «Ты — спичрайтер министра. Из этих материалов собери записку для зам. губернатора на одну страницу, по структуре: Контекст / Главный вывод / 3 ключевых факта / Что предлагаем / Главный риск. Без формул, без терминов, без слова "корреляция".»
3. Получите черновик. **Не сдавайте его как есть.** Найдите минимум 5 мест, где ИИ либо смягчил угол, либо натянул вывод, либо использовал шаблонную формулировку. Перепишите вручную.
4. Финальная версия — **строго одна страница** (или 1500 знаков, если в Markdown).
5. **Отдельным блоком в конце** — пять терминов, которые вы намеренно НЕ использовали в записке, и чем вы их заменили (например, «корреляция» → «связь, требующая проверки»).
