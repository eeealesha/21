### Задание 1: Аудит выгрузки от МИАЦ — ⏱ 60 мин

**Для выполнения нужно знать:** типичные ошибки медицинских данных (опечатки в кодах, дубли пациентов, аномалии времени, пропуски, выбросы), различие между «техническим браком» и «содержательной аномалией».

ТЗ ушло — выгрузка пришла. Прежде чем считать гипотезы, убедитесь, что вы считаете не мусор.

**Проходной порог — найти 6 из 8 классов. Найти все 8 — на отличную оценку.**

**Старт:** шаблон [`materials/template_data_quality_review.md`](materials/template_data_quality_review.md) — готовая форма промпта ИИ-аудитору и таблица для фиксации находок.

**Выполни следующие шаги:**

1. Откройте `dataset_v2.csv` в Numbers / Google Sheets. **Применяйте 6 приёмов поиска** — этого хватает на 7 из 8 классов:
   - **Сортировка по `time_to_ivl_min`** (по возрастанию) — увидите аномально низкие значения (4 мин) **и** подозрительные значения с 3 знаками после запятой (восстановленные данные).
   - **Фильтр `vacancy_reanim_pct < 0`** — найдёте отрицательную вакансию.
   - **Сортировка по `month`** в алфавитном порядке — опечатки названий (`сентябь`, `янврь`, `нобярь`) встают рядом с нормальными значениями.
   - **Сводная по `(mo_id, year, month)` с подсчётом** — дубликат ключа покажется как `count = 2`.
   - **Фильтр в `population` по нечисловым значениям** — найдёте `н/д`.
   - **Фильтр `ivl_units = 0`** — найдёте несогласованность: нулевое количество аппаратов ИВЛ при ненулевом `time_to_ivl_min`.

   Восьмой класс (содержательные нули `letality_pct` при ненулевом `admitted`) — **сортировка по `letality_pct` снизу**.

   **Не считайте формулами анализа** — задача аудита, не анализа.
2. По шаблону сформулируйте промпт ИИ-аудитору (роль «опытный data quality инспектор Минздрава»): подтвердить ваши находки и предложить дополнительные классы проблем. Покажите ИИ заголовки + 10 первых строк.
3. Проверьте каждую гипотезу аудита вручную. По каждой запишите: подтвердилось / нет, на скольких строках, что это значит для анализа.
4. Для проблем класса «технический брак» (опечатки, пропуски, выбросы) сформулируйте, как именно исправлять (медиана / отбросить строку / запросить у МИАЦ повтор).
5. Для проблем класса «содержательная аномалия» (например, аномально низкое время до ИВЛ) сформулируйте, **какие управленческие действия** должны последовать — *не правка данных, а проверка процесса в МО*.

**Результат:** файл `task1_data_quality_review.md` в папке группы.

> Важно различать: технический брак исправляется в файле; содержательная аномалия исправляется в реальности.

### Задание 2: Проверка гипотез Дня 1 — ⏱ 75 мин

**Для выполнения нужно знать:** корреляция vs причинно-следственная связь, понятие конфаундера (третьей переменной), почему «эффект на средние» может скрывать обратный эффект на подгруппе.

Берёте 3–5 гипотез из вчерашнего файла `День_1/task4_hypotheses.md`. Сегодня — момент истины.

**Выполни следующие шаги:**

1. Для каждой гипотезы сформулируйте промпт к ИИ: «У нас вот такой датасет с такими полями [список]. Гипотеза: [текст]. Опиши пошагово, какой анализ нужно сделать, чтобы её проверить (на словах, без кода). Что должно получиться, если гипотеза верна? Что — если неверна?»
2. Запишите план проверки для каждой гипотезы. На этом этапе вы **не считаете**, а формулируете методику.
3. Откройте сводную справку [`materials/precomputed_summary.md`](materials/precomputed_summary.md) — готовые агрегаты по основным разрезам (по регионам, по уровням вакансий, по `time_to_ivl_min`, по 3 «горячим» МО). Сопоставьте цифры с каждой гипотезой. **Если нужного среза в справке нет — это тоже результат:** значит, вы спросили данные, которых пока не считают (пункт в ТЗ для МИАЦ v2, бонус Дня 3).
4. По каждой гипотезе зафиксируйте вердикт:
   - **Подтверждена** (с цифрой эффекта)
   - **Опровергнута**
   - **Частично подтверждена** (в каких подгруппах работает, в каких нет)
   - **Невозможно проверить на этих данных** (чего не хватает)
5. **Отдельным разделом — предупреждения о причинности.** Где в вашем анализе наибольший риск спутать корреляцию с причиной? Что вы НЕ имеете права утверждать перед губернатором, даже если корреляция есть?

**Результат:** файл `task2_hypotheses_check.md` в папке группы.

### Задание 3: Wireframe дашборда главврача — ⏱ 90 мин

**Для выполнения нужно знать:** принципы UI/UX дашборда (одна цель = один дашборд, верхняя строка — ключевые KPI, фильтры справа, инсайт сверху-слева), правило «5 секунд», различие операционного и стратегического дашборда.

Главврач крупной МО Региона Б — пользователь номер один. Он не аналитик. Он смотрит дашборд утром между обходами. Если за 5 секунд непонятно, **что нужно делать** — дашборд не работает.

**Старт:** шаблон [`materials/template_wireframe.md`](materials/template_wireframe.md) — опорный ASCII-эскиз правильной компоновки и пример спецификации виджета. Используйте как референс, **не копируйте**.

**Выполни следующие шаги:**

1. Сформулируйте, какое **управленческое действие** должен провоцировать дашборд (одно предложение). Без этого — не начинайте.
2. На листе А3 (или в Miro/FigJam) нарисуйте wireframe. Минимальные требования:
   - 4–6 виджетов
   - Верхняя строка — 3–4 KPI с цветовым кодом
   - Левая большая зона — главный график/тепловая карта
   - Правая колонка — фильтры (период, МО, специальность)
   - Внизу — таблица «топ-5 проблемных МО» или аналогичный «список к действию»
3. Для каждого виджета объясните: что меряет, какой источник из `dataset_v2.csv`, какое действие провоцирует.
4. Покажите ИИ описание главного виджета и спросите: «Какие 3 типовые ошибки UI/UX в этом виджете я могу совершить?» Запишите ответ и проверьте свой wireframe против него.

**Результат:** `task3_wireframe.png` (скан/экспорт макета) + `task3_dashboard_spec.md` (текстовое описание).

> «Анти-дашборд» (контрпример «отчёт ради отчёта») перенесён в **бонусные критерии** чек-листа.

### Задание 6: Аналитическая записка для зам. губернатора — ⏱ 60 мин

**Для выполнения нужно знать:** структура аналитической записки (Контекст → Главный вывод → 3 ключевых факта → Решение → Риски), правило «один экран, одна страница», язык управленческой коммуникации (без p-value, без терминологии).

Зам. губернатора прочитает вашу записку за 90 секунд между двумя совещаниями. Если за 90 секунд он не поймёт, **что вы предлагаете и почему**, — записка провалилась.

**Старт:** пример готовой записки — [`materials/insights_note_example.md`](materials/insights_note_example.md).

**Выполни следующие шаги:**

1. Откройте свои артефакты дня: `task1_data_quality_review.md`, `task2_hypotheses_check.md`, `task3_dashboard_spec.md` — это весь ваш материал.
2. Сформулируйте промпт к ИИ: «Ты — спичрайтер министра. Из этих материалов собери записку для зам. губернатора на одну страницу, по структуре: Контекст / Главный вывод / 3 ключевых факта / Что предлагаем / Главный риск. Без формул, без терминов, без слова "корреляция".»
3. Получите черновик. **Не сдавайте его как есть.** Найдите минимум 5 мест, где ИИ смягчил угол, натянул вывод или использовал шаблонную формулировку. Перепишите вручную.
4. Финальная версия — **строго одна страница** (или 1500 знаков в Markdown).
5. **Отдельным блоком в конце** — пять терминов, которые вы намеренно НЕ использовали, и чем их заменили (например, «корреляция» → «связь, требующая проверки»).
