# Чек-лист: День 2 — Анализ данных и проектирование дашборда

> 4 основных задания + 2 бонусных. Сами задания — в [`readme.md`](readme.md).

## Введение

Этот проект выполняется в группах 3–5 человек. Проверки:

- Это второй день: чек-лист строже, потому что ваш опыт вырос. Не делайте скидку «мы только начинаем».
- Обращайте внимание на сцепку с Днём 1. Если гипотезы Дня 2 не имеют ничего общего с гипотезами Дня 1 — группа потеряла нить.
- Защищать дашборд устно — обязательная часть. Если группа не может за 60 секунд рассказать, какое действие провоцирует их дашборд, — дашборд не работает, как бы красиво он ни выглядел.

## Шкала оценки

- **Зачтено — «хорошо»:** ≥ 80 % обязательных критериев + ответ на вопрос проверки.
- **Зачтено с замечаниями:** 60–80 %.
- **Не зачтено:** < 60 % ИЛИ нет ответа на вопрос проверки голосом.

**Для прохождения дня:** зачтены **все 4 основных задания** (1, 2, 3, 6); допустимо «3 из 4». Финальная защита дашборда (Задание 3) устно — обязательное условие зачёта Задания 3, даже если все галочки стоят. Бонусные задания (4, 5) на порог прохождения **не влияют**.

**🔴 Критические критерии.** Под каждым заданием 2–3 пункта помечены 🔴 — без них задание **не зачтено**.

**Бонусные критерии** под каждым заданием — отличают «хорошо» от «отлично».

## Задание 1: Аудит выгрузки от МИАЦ

**Цель:** проверить навык систематического аудита данных и разделение технического и содержательного.

- [ ] **🔴 КРИТИЧНО:** В папке группы есть `task1_data_quality_review.md`.
- [ ] Приведён исходный промпт ИИ-аудитору.
- [ ] **🔴 КРИТИЧНО:** Зафиксировано **минимум 6 из 8 классов проблем** v2 с конкретным примером строки: «восстановленные» `time_to_ivl_min` (3 знака после запятой), дубликат `(mo_id, year, month)`, отрицательная `vacancy_reanim_pct`, аномально низкое `time_to_ivl_min = 4`, подозрительные `letality_pct = 0`, `ivl_units = 0` при ненулевом времени до ИВЛ, опечатки в `month`, тип-микс в `population`.
- [ ] По каждой проблеме указано: подтвердилось / нет, на скольких строках.
- [ ] **🔴 КРИТИЧНО:** Чётко разделены **технический брак** (исправляется в данных) и **содержательная аномалия** (исправляется в реальности процесса МО).
- [ ] Для технических ошибок указан конкретный метод исправления.
- [ ] Для содержательных аномалий указано управленческое действие (с кем поговорить, что проверить).

**Бонусные критерии:**
- [ ] Найдены **все 8 классов** (не 6).
- [ ] Для хотя бы одной «содержательной аномалии» предложен **конкретный регламент** в МО (а не «уточнить у главврача»).

**Вопрос для проверки понимания:**
> «Если в одной МО `time_to_ivl_min = 4 минуты`, это техническая ошибка или содержательная аномалия? Как вы её отнесёте и почему?»

- [ ] **🔴 КРИТИЧНО:** Для каждой гипотезы — явный вердикт: подтверждена / опровергнута / частично / невозможно проверить (с обоснованием).

## Задание 3: Wireframe дашборда главврача

**Цель:** проверить навык проектирования дашборда от управленческого действия, а не от «красивых графиков».

- [ ] **🔴 КРИТИЧНО:** В папке группы есть `task3_wireframe.png` (или `.jpg`, `.pdf`) **и** `task3_dashboard_spec.md`.
- [ ] **🔴 КРИТИЧНО:** В spec-файле — одно явно сформулированное управленческое действие, на которое должен провоцировать дашборд.
- [ ] На wireframe — 4–6 виджетов, не больше.
- [ ] Верхняя строка содержит 3–4 ключевых KPI.
- [ ] Главный график — слева/сверху и крупный.
- [ ] Фильтры — справа, не сверху и не разбросаны.
- [ ] Внизу — «список к действию» (топ-N проблемных МО или аналог).
- [ ] Для каждого виджета — текстовое описание: что меряет, какой источник, какое действие.
- [ ] Приложен ответ ИИ на вопрос о 3 типовых ошибках UI/UX в главном виджете и видно, как группа учла критику.

**Бонусные критерии:**
- [ ] Сделан **анти-дашборд** на отдельном листе (тот же набор данных в виде «отчёт ради отчёта»: пай-чарты, 3D, легенды на пол-экрана) с пояснением, что в нём не так.
- [ ] В спеке главного виджета указан конкретный **SLA реакции** («главврач должен отреагировать на красную зону за N часов») с обоснованием.
- [ ] Wireframe прошёл «**тест 5 секунд**» от незаинтересованного участника другой группы (отметка с подписью в spec).

**Вопрос для проверки понимания:**
> «Покажите мне ваш дашборд на 5 секунд. (Засеките таймер.) Я только что увидел его. Что я должен сделать первым делом?»

**Цель:** проверить навык управленческой коммуникации без терминологии.
