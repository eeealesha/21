# Чек-лист: День 1 — Дизайн подхода на основе данных

## Введение

Этот проект выполняется в группах 3–5 человек. Проверки в проекте очень важны:

- Проверки — это не просто формальная сверка ответов, а ключевой этап обучения. Вы обменяетесь подходами, услышите аргументы коллег и увидите, как одну и ту же задачу можно решать по-разному.
- Проверяя другую группу, вы получаете доступ к чужому ходу мысли — это редкая возможность для управленца увидеть «как ещё бывает».
- Обсуждайте проблемы вслух. Если непонятно — спрашивайте. Если нашли ошибку — предложите, как её исправить, а не просто фиксируйте.
- Главное — открытый диалог. Все группы идут к одной цели: за три дня собрать защищаемую программу для Минздрава.

## Шкала оценки

По каждому заданию суммируйте выполненные критерии (галочки `[ ]` ниже):

- **Зачтено — «хорошо»:** выполнено ≥ 80 % обязательных критериев и группа отвечает на вопрос проверки понимания.
- **Зачтено с замечаниями — «удовлетворительно»:** выполнено 60–80 % критериев; на вопрос отвечает неуверенно, но по существу.
- **Не зачтено:** выполнено < 60 % ИЛИ группа не может ответить на вопрос проверки понимания голосом.

**Для прохождения дня:** минимум 4 из 6 заданий зачтены. Если на одно задание стоит «не зачтено», это не приговор — но это сигнал группе пересобрать артефакт перед сном.

**🔴 Критические критерии.** Под каждым заданием 2–3 пункта помечены 🔴 — это критические критерии: без них задание **не зачтено**, даже если все остальные пункты выполнены. Это защита от «количество вместо качества» (например, 9 галочек из 10, но не сформулирована корневая проблема).

**Бонусные критерии** (под каждым заданием отдельно) — для отличия «хорошо» от «отлично». Не входят в обязательный минимум, но фиксируются проверяющим устно.

## Общие правила проверки

- Подлежат проверке только те файлы, которые проверяемая группа выложила в свою папку `src/<номер_группы>/День_1/`.
- Убедитесь, что вы проверяете именно ту группу. Чужие файлы — не оценивать.
- Если вы не закончили День 1 сами — обязательно перечитайте задания перед проверкой.
- **EMPTY WORK** — флаг, если папка пуста или сданы файлы под другими именами. Продолжите проверку, чтобы помочь разобраться.
- **CHEAT** — флаг, если группа не может объяснить артефакт голосом (явный признак, что ИИ написал, а никто не читал). Продолжите проверку.

## Задание 1: Дерево факторов

**Цель:** проверить умение декомпозировать управленческую проблему на измеримые факторы и критически использовать ИИ.

- [ ] **🔴 КРИТИЧНО:** В папке группы есть `task1_decomposition_tree.md`.
- [ ] Указана корневая проблема одной чёткой фразой (не «летальность», а конкретное утверждение про разрыв с Регионом А).
- [ ] Приведён исходный промпт к ИИ — с ролью, контекстом, ограничениями и форматом ответа.
- [ ] Приведён сырой ответ ИИ (как был, без редактирования) — отдельным блоком.
- [ ] Приведено отредактированное командой дерево с глубиной 3–4 уровня.
- [ ] **🔴 КРИТИЧНО:** Каждый фактор помечен флагом `[управляем]` / `[влияем косвенно]` / `[не управляем]`.
- [ ] Выделены 5–7 веток, на которые группа намерена опереться. Каждая — управляема и измерима.
- [ ] Написано краткое объяснение, что и почему было отброшено.
- [ ] **🔴 КРИТИЧНО:** Есть отдельный блок «Межотраслевой перенос» с **ровно 1** практикой из ритейла или финтеха (2+ — бонус, не обязательно).
- [ ] Указана конкретная аналогия (не «там тоже бывают выбросы»).
- [ ] Указана граница применимости — где правило ломается о медицинскую специфику.

**Бонусные критерии:**
- [ ] В дереве факторов есть хотя бы одна **контринтуитивная** ветка, к которой команда сама пришла, без подсказки ИИ.
- [ ] В блоке «Межотраслевой перенос» приведено **2 практики** из разных отраслей, с сравнением их применимости.

**Вопрос для проверки понимания:**
> «Какой фактор вы изначально считали важным, но после критического разбора отбросили? Почему?»

## Задание 3: Экспертная шкала ИИ

**Цель:** проверить способность отделять задачи, где ИИ полезен, от задач, где он опасен.

- [ ] **🔴 КРИТИЧНО:** В папке группы есть `task3_ai_delegation.md`.
- [ ] **🔴 КРИТИЧНО:** Разобраны все 10 ситуаций (без пропусков).
- [ ] Каждая отнесена к одной из трёх категорий (🟢 / 🟡 / 🔴).
- [ ] Для каждой ситуации — обоснование 2–3 предложениями.
- [ ] Для каждой ситуации указан конкретный контроль со стороны человека (что именно человек должен перепроверить).
- [ ] **🔴 КРИТИЧНО:** В категории 🔴 («только человек») находятся как минимум ситуации 2 («поставить диагноз пациенту») и 9 («подписать приказ»). Без этого — серьёзный сигнал, что группа не уловила суть шкалы.

**Бонусные критерии:**
- [ ] Группа предложила свою четвёртую категорию «🟡 с условием» — ИИ-ассистент только при наличии конкретной верификации, с одним примером.
- [ ] Для одной ситуации показано, **как меняется категория** в зависимости от контекста (например, тот же диагноз — но по рентгенограмме вместо словесного анамнеза).

**Вопрос для проверки понимания:**

## Задание 4: Лаборатория гипотез

**Цель:** проверить навык формулировать проверяемые гипотезы с измеримыми показателями.

- [ ] **🔴 КРИТИЧНО:** В папке группы есть `task4_hypotheses.md`.
- [ ] **🔴 КРИТИЧНО:** Гипотез — от 3 до 5 (не меньше, не больше).
- [ ] **🔴 КРИТИЧНО:** Каждая гипотеза сформулирована как утверждение, а не как вопрос; указаны измеримый показатель, направление эффекта и условие опровержения.
- [ ] Для каждой указан измеримый показатель.
- [ ] Для каждой указано направление эффекта (выше / ниже / нелинейно).
- [ ] Для каждой перечислены данные, нужные для проверки.
- [ ] Для каждой написано условие опровержения: что нужно увидеть, чтобы признать гипотезу неверной.
- [ ] Хотя бы одна гипотеза — контринтуитивная (объяснено почему).
- [ ] Приложен сырой ответ ИИ с критикой исходных формулировок.

**Бонусные критерии:**
- [ ] Есть гипотеза, которая **опровергает общепринятую интуицию** региона (например, «возраст оборудования сам по себе не влияет на летальность — влияют только вакансии»).

**Вопрос для проверки понимания:**
